# ZE Laser Practice

A browser trainer for CS2 Zombie Escape laser stages and bosses. You spawn where the lasers are and the
**map's own entity logic** runs the stage, 1:1 with a CS2Fixes ZE server (GFL-style). Inspired by
cybo's lasers.cybo.dev, and it writes **his map-folder format** so he can reuse our baked maps.

Read [README.md](README.md) first: the map folder format, scenarios, bosses, the code layout.
[ROADMAP.md](ROADMAP.md) is what's shipped and what's next. Tick boxes as things land, add what you defer.

## Layout

```
bake/        lasers-bake (C#, NuGet ValveResourceFormat 20.1): workshop VPK -> map folder; --panorama; --stock-sounds
web/         the game (Vite + three.js, plain ES modules, no framework)
  src/app/     state, settings, session, loop, input, bosses, endless, records
  src/ui/      menu, hud, overlay, touch (+ their css)
  src/world/   collision, movement, render, assets, entities/ (engine + classes/)
  src/audio/   audio.js
  src/weapons/ viewmodel.js + fp/ (vpkstuff's previewer engine, kept verbatim so fixes can flow both ways)
  src/lib/     shared helpers (dom, math, ...): reuse these, never re-implement them
  public/scenarios/   hand-written stage definitions (committed)
  public/maps|sounds|panorama|weapons/   generated by the bake / copied assets (gitignored, large, Valve content)
tools/       io-graph.mjs (scenario authoring), index-maps.mjs
```

## Run

```bash
npm --prefix web install
npm --prefix web run dev            # http://localhost:5804  (.claude/launch.json: "web")
dotnet build bake -c Release        # then see README "Run it locally" for the bake commands
```

## Rules

- **Truth sources, not memory.** "1:1" means the number comes from: the map's own entity data
  (`tools/io-graph.mjs`), CS2's binary behaviour (`D:\_cursor projects\cs2map\porter\research\docs\07_RUNTIME_SEMANTICS.md`),
  CS2Fixes / ZR (`D:\_gfl\CS2Fixes\src`, loadouts, armor, ammo), GFL's configs (github.com/gflze/CS2-ZE-Configs:
  bosshud, stripper, mapcfg) and CS2's own Panorama files (`lasers-bake --panorama`). If the user remembers something
  different from the data, say so with the evidence.
- **No monoliths, no duplicates.** Files stay focused (~100-400 lines). Anything used in two places goes in
  `web/src/lib/` (or the module that owns it) and is imported, never copied. Name things for what they do.
- **Security.** Everything from a map, a scenario, the URL or localStorage is untrusted: escape it before
  `innerHTML` (`lib/dom.js` `esc`), validate names before using them in paths (`lib/paths.js`), never `eval` /
  `new Function` / inline handlers. The bake must never write outside its output folder (VPK paths are
  attacker-controlled: sanitise every path built from them). Keep the CSP in `web/index.html` tight.
- **Never write into the CS2 install.** The old VRF CLI ignores `-o` for `.uifont` and once wrote into
  `game/csgo/panorama/fonts`; use lasers-bake (VRF 20.1) for anything Valve-side.
- **Browser checks: Chrome MCP** (`mcp__claude-in-chrome__*`) against `http://localhost:5804`.
  `window.__lasers` is the debug handle: `startScenario(i, mode)`, `advance(seconds)` (synchronous sim; a hidden
  tab gets no animation frames), `scenarios()`, `engine`, `player`, `run`, `settings`, `audio`, `vm`;
  `window.__lasersInput = (t) => ({forward, side, jump, duck, walk})` drives the player. Tests in the user's Chrome
  are audible: keep the game paused (audio is silent while paused) and never leave test values saved in their
  settings (`localStorage['lasers.settings']`).
- **Bash heredocs mangle backslashes on this machine** (`\\` -> `\`): write scripts with the Write tool.
- **Commit explicitly** (`git add <files>`, never `-A`), confirm `git diff --cached --name-only` first.
  GitHub repos default **private**; ask before creating or pushing one.
- Platform: Windows dev box (PowerShell + Git Bash). CS2 at `D:\Steam\steamapps\common\Counter-Strike Global Offensive`;
  workshop maps in `D:\Steam\steamapps\workshop\content\730\<item>`.
